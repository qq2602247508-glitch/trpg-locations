# 长执行路线与验收门槛

本项目按“规则资产逐步增加、核心契约保持稳定”的方式扩展。里程碑不是场景名称数量，而是每一类空间语法都能持续产出不同、合理、可战斗的结果。

## 已完成：第一阶段垂直切片

- 固定 5 英尺格与米制世界坐标
- 可复现的带种子随机流，子系统随机性互不污染
- `GeneratedScene` 中间表示：房间、图元、路线、战术点、诊断
- 酒馆、塔楼、下水道、洞窟四种不同拓扑
- 未识别输入的特征分解和组合式降级
- Three.js 实例化渲染、楼层剖切、路线与战术覆盖层
- 几何级验证：边界、承重、墙体穿越、开口、垂直交通、水流与坡道

## 第二阶段：建筑语法库（进行中）

当前已落地第一批独立建筑原型：教堂、神殿、庄园、兵营、图书馆、工坊、仓库、堡垒和矿井。它们共享验证契约，但在中轴圣所、庭院翼楼、操练厅、书库/回廊、作业跨/装卸、幕墙/角塔和巷道/竖井等空间组织上使用不同布局算法。灯塔由多层塔楼语法覆盖。

把建筑拆成“用途图、体量、房间组织、交通、外壳、战术布置”六层规则。下一批继续加入监狱、剧院、宫殿和大型城门；每个专用生成器必须声明自己的比例与拓扑差异，不能只换材质。

尺寸使用分布而不是常数。例如：

- 酒馆公共层常见净高约 10–14 ft，客房层约 9–12 ft，总层数在 1–3 层间受规模和功能影响。
- 塔楼单层常见约 12–16 ft，狭长垂直交通占用独立战术面积，层数和直径共同限制有效战斗空间。
- 庄园由主楼、服务翼、庭院和附属建筑共同确定占地；规模不能通过等比例拉伸单一矩形获得。
- 下水道由主渠坡度、支渠汇流、检修步道、溢流室、竖井和地表入口共同决定上下关系。

所有范围都进入按原型、规模和种子加权的分布，并由可达性与空间约束截断。

## 第三阶段：聚落与城市规划器（进阶版已落地）

当前已落地村庄、城镇、城市、港区的共享规划管线：多段弯折道路图、中心广场、功能区标签、水岸、密度传播、区内/区际关系图、按道路切开门户的城墙，以及具有流量权重的市民、市场、服务和港口货运路线。昼夜时段已落地：白昼市场/通勤、全天服务、夜间城墙巡逻使用独立路线层，UI 可切换时段并同步光照；下一步继续增加屋顶路线与区块流式加载。

城市规划器只负责组合，不替代独立建筑生成器：

1. 根据水岸、坡度、城墙、门户与地标建立不可违反的地理约束。
2. 生成主路骨架、次级道路和巷道，保证连通并保留非规则街廓。
3. 传播功能区与地价梯度，决定建筑密度、用途、人流和昼夜变化。
4. 从建筑语法库选择独立地块实例，依据临街面、消防间距、院落和后勤入口落位。
5. 生成地标视线、市场拥堵、巡逻路线、屋顶路线和战斗瓶颈。
6. 按区块流式生成；远处只保留体量，进入战斗范围后再实例化内部结构。

村庄、城镇、港区和大城市共享规划管线，但使用不同的道路层级、中心数量、密度曲线和基础设施权重。

## 第四阶段：自然与特殊战术空间（基础版已落地）

当前已落地河谷、裂谷、山地、冰原、遗迹和地下湖六类语法，并为每类建立小/中/大规模回归。后续继续增加林地、沼泽、沙漠、火山、完整幽暗地域群落与更细的地形网格。

自然空间采用地形场、侵蚀/水系和通行图，不套房间模板。覆盖河谷、裂谷、幽暗地域、山地、河流、冰原、遗迹和地下湖。生成顺序为地貌大形、可通行层、路线网络、掩体/危险、叙事地标和视觉细节。

每个结果至少具有：主路线、可识别的替代选择、高低差、战术掩体、危险区域与尺度参照。坡道、桥梁、攀爬点和跳跃点必须在几何与路线数据中同时存在。

## 第五阶段：语义与本地模型

Ollama 只输出受 schema 约束的意图层：题材、环境、拓扑偏好、高差、水体、光照、掩体、主题、地标和危险词。该层已接入 `qwen3.6:35b-mlx`，并且仅在本地分类没有证据时调用。尺寸、拓扑边、随机数、碰撞、可达性和修复始终由确定性代码负责。模型不可用、超时或返回非法数据时，使用本地分类和组合式特征分解继续生成。

## 第六阶段：性能与交付

- 超过 60 格的世界按 28 格空间块分批并使用视锥剔除（已落地）；后续增加多级几何 LOD 和材质图集
- Web Worker 承担大地图规划和验证（已落地，含无 Worker 回退）
- Three.js 渲染核心延迟加载，生成器与首屏 UI 分块（已落地）
- 聚落建筑实例清单与独立外部模块（已落地）；每个实例保留 Seed、楼层、逐层层高和占地，后续可按需展开完整室内
- 大型城市分区流式加载，建筑内部按需生成
- 场景 JSON 存档、种子复现、战术图导出和可选 Blender/glTF 管线
- 桌面浏览器性能预算与不同规模的基准场景

## 自动验收

每次合并必须通过：

- 同请求同 Seed 完全复现；不同 Seed 不退化为同一布局
- 多规模、多密度、多 Seed 的批量矩阵；当前压力门槛为 756 个固定域组合加未知题材回归
- 路线不穿实墙，门洞、楼梯、梯子、桥和坡道具有对应实体
- 垂直路线有承重和楼板开口；水流连续且不逆坡
- 房间、建筑、道路和地形均在各自合理尺寸带内
- 未知输入能生成可玩的组合结果，不能返回空场景或通用垃圾盒子
- TypeScript、单元测试、生产构建和 `git diff --check`

## 人工验收

用户可按同一组 Seed 检查：

- 关闭调试层时，场景轮廓和用途是否一眼可读
- 打开路线后，主路、替代路和跨层路线是否真的可走
- 切换单层后，是否没有其他楼层的悬浮标记
- 以 5 英尺格估算门、房间、楼梯、渠宽、平台和建筑总体尺寸是否可信
- 连续生成 10 次，比例、入口、房间组织和战术选择是否有明显变化但仍属于同一原型
- 输入未收录的新题材，结果是否由已知空间能力合理组合，而不是变成固定默认场景

每个里程碑都应同时提供自动测试结果、浏览器控制台结果和代表性截图；未完成这些证据时只算开发中，不算交付。
